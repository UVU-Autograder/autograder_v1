# UVU Autograder — Decisions

This file tracks current product and implementation decisions.

## Decision Log

| Decision                                 | Choice                                                                                                                                                 | Rationale                                                                                                                                                      |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Backlog tool                             | GitHub Projects (Issues + Milestones) + [backlog.md](../planning/backlog.md)                                                                           | Repo-local, free, and simple                                                                                                                                   |
| Data retention                           | Sandbox: immediate wipe after results. Official: identifiable review/export artifacts may exist ≤24h or until staff cleanup, then destroyed            | Supports staff review/export without persistent education-record storage                                                                                       |
| Database scope                           | Store staff/course metadata, assignments/configs, lightweight artifact metadata, derived projections when needed, and sanitized run metadata only      | Keeps persistent data small and non-sensitive                                                                                                                  |
| Execution stack                          | Judge0 CE with Kata Containers isolation                                                                                                               | Current execution engine and isolation model                                                                                                                   |
| AI inference                             | Local LLM on university-managed infrastructure                                                                                                         | Privacy posture; on-prem inference                                                                                                                             |
| Local LLM scope                          | Sandbox only for now; code (+ grounded test/AST context) only if not personally traceable                                                              | Official and other surfaces deferred; PII/identifiers must not reach the model                                                                                 |
| Auth (current)                           | Mock JWT login at `/auth/mock-login` with `@uvu.edu` addresses. Student sandbox requires no authentication.                                            | Enables development and staff workflows without OAuth infrastructure yet                                                                                       |
| Auth (deferred)                          | NextAuth + Microsoft OAuth for staff                                                                                                                   | Planned; not active sprint work                                                                                                                                |
| UVU restriction                          | Reject non-`@uvu.edu` staff logins                                                                                                                     | Keeps staff/admin access bounded to UVU users                                                                                                                  |
| Student access model                     | Session-only sandbox access to globally visible sandbox-enabled assignments                                                                            | Avoids student-specific schedule or roster lookups                                                                                                             |
| Sandbox visibility source                | `sandbox_enabled` assignment visibility only                                                                                                           | Assignment-driven rather than roster-driven                                                                                                                    |
| Assignment content source                | Canvas-managed                                                                                                                                         | Canvas remains the source of truth for course content and grades                                                                                               |
| Assignment ownership                     | Course-shared assignment setup                                                                                                                         | Section scope focuses on access and runs                                                                                                                       |
| Config authoring model                   | Wizard-first with app-owned `assignment_configs.config_json`                                                                                           | Guided UI authoring; config is internal                                                                                                                        |
| Multi-file support                       | ZIP/project bundle uploads for official and sandbox workflows                                                                                          | Realistic coursework with a narrow upload contract                                                                                                             |
| Bundle requirements                      | Required files, entrypoint, and layout expectations live in the app-owned assignment config                                                            | Same source of truth as grading setup                                                                                                                          |
| Concept policy                           | Progressive whitelist via `Concepts Covered`; effective allowed concepts = course defaults ∪ module concepts                                           | Aligns AST checks and LLM context; per-assignment concept table/additions removed                                                                              |
| Sandbox output                           | On-screen only                                                                                                                                         | Avoids downloadable sandbox artifacts                                                                                                                          |
| Sandbox upload model                     | ZIP/project bundle upload only                                                                                                                         | No loose multi-file drag-and-drop contract                                                                                                                     |
| Official rate limiting                   | No sandbox-style cap                                                                                                                                   | Staff uploads are not student-limited                                                                                                                          |
| Sandbox rate limiting                    | `5 uploads per hour` per sandbox session                                                                                                               | Controls abuse without requiring student identity                                                                                                              |
| Official export shape                    | Two separate staff downloads: Canvas-grade CSV and per-student HTML feedback ZIP                                                                       | Explicit exports without a combined package                                                                                                                    |
| Canvas feedback distribution             | Deferred                                                                                                                                               | Manual Canvas grade CSV import remains assumed                                                                                                                 |
| Official review workflow                 | Staff review with exports; in-app manual grading Active (API persist/export regen done); preview/Monaco/filtering still backlog                         | Not permanently “preview-only”                                                                                                                                 |
| Manual or non-code grading               | Supported; workflow in progress                                                                                                                        | Reflections and code-quality rubric items without automated execution                                                                                          |
| Artifact storage                         | Hybrid                                                                                                                                                 | Config/metadata in Postgres; file bodies behind a storage abstraction                                                                                          |
| Frontend editor                          | Locally hosted read-only Monaco preview                                                                                                                | Preview and review surface, not an in-browser IDE                                                                                                              |
| Test authoring                           | Wizard, app-owned config, and pytest artifacts                                                                                                         | No separate simple test-case editor                                                                                                                            |
| Assignment pytest shape                  | One or more pytest file artifacts per assignment                                                                                                       | Supports complex CS 1410 assignments                                                                                                                           |
| Test scoring mapping                     | `config_json.tests[].key` maps to pytest marker `ag_<key>`                                                                                             | Stable markers; one scoring item may cover multiple pytest functions                                                                                           |
| Derived test projections                 | `scoring_items` regenerated from canonical config; never editable grading truth                                                                        | No second source of truth                                                                                                                                      |
| Testing standard                         | Risk-based unit, integration, cleanup, FERPA, and stress coverage                                                                                      | Focus on high-risk workflows                                                                                                                                   |
| Workspace lifecycle                      | Explicit shared integration                                                                                                                            | Cleanup is core retention behavior                                                                                                                             |
| Cleanup proof standard                   | Automated integration evidence plus Dell-workstation operational spot checks when host access exists                                                   | Repeatable regression + real-runtime evidence                                                                                                                  |
| Permission baseline                      | Actors are `admin`, `instructor`, `IA`, and public sandbox; section-scoped staff access enforced on official ingest/run/status routes                  | Course-shared setup with section-scoped run authority                                                                                                          |
| Admin management scope                   | Admins manage courses, sections, staff accounts, roles, access grants, and admin-only monitoring                                                       | Operational monitoring stays off instructor/IA surfaces                                                                                                        |
| IA assignment-config authority           | Read-only                                                                                                                                              | IAs run and review official workflows in assigned sections                                                                                                     |
| Student history                          | No persistent sandbox attempt history                                                                                                                  | Retention alignment                                                                                                                                            |
| Run summary shape                        | Minimal aggregate metadata only                                                                                                                        | Avoids freezing sensitive detail into persistent storage                                                                                                       |
| Logging posture                          | Persistent logs and run metadata are aggregate-only and non-identifying; sensitive debug traces are short-lived only                                   | Avoid recreating education records through ops data                                                                                                            |
| Execution-artifact retention             | Judge0 submission/result artifacts and Kata execution state are destroyed immediately after verification and retrieval                                 | Zero-retention at the execution-service boundary                                                                                                               |
| Validation data                          | Prefer fake/synthetic or completely anonymized data until live-data posture is confirmed for a workflow                                                | Avoids premature live student-record handling                                                                                                                  |
| Canvas validation target                 | Synthetic Canvas ZIP/CSV fixtures plus any completely anonymized Canvas-shaped samples                                                                 | Non-identifying parser coverage                                                                                                                                |
| Hosting target                           | Local/on-prem on the Dell workstation                                                                                                                  | Judge0 + Kata depend on local Docker/hardware                                                                                                                  |
| Frontend preview                         | Vercel mockup at https://autograder-frontend-mockup.vercel.app/                                                                                        | Rapid UI preview; production API remains on-prem                                                                                                               |
| Capacity planning                        | Concurrency is memory-bound and benchmarked on the Dell workstation                                                                                    | Prevents peak-load overcommit                                                                                                                                  |
| Execution-slot cap                       | Default cap is `2` concurrent Judge0/Kata grading jobs; benchmark `3` and `4`; do not exceed `4` without new evidence                                  | Keeps the 32GB Dell workstation stable                                                                                                                         |
| Queue admission (policy)                 | Warn at `40` waiting jobs; reject at `50`; fair official/sandbox scheduling into the slot cap                                                          | Shared `queue_admission` module; workers use `-Q sandbox,official,default`                                                                                      |
| Judge0 language mapping                  | Configurable `JUDGE0_LANGUAGE_ID` env var defaulting to `71` (Python 3)                                                                                | Decouples backend from a specific Judge0 image ID                                                                                                               |
| Judge0 timeout                           | Default `TEST_EXECUTION_TIMEOUT_SECONDS` is `30`                                                                                                       | Matches current settings; not 10s                                                                                                                              |
| Output normalization                     | Custom `normalizer.py` utility                                                                                                                         | Focused whitespace/line-ending normalization without Submitty-internal deps                                                                                    |
| Seed artifact resolution                 | `seed://` URIs resolve to `backend/app/db/seeds/`                                                                                                      | Co-locates seed packages with the backend image and `seed.py`                                                                                                  |
| Pytest execution in Judge0               | Generated runner as `source_code`; student/test files as `additional_files` ZIP; structured JSON after a delimiter                                     | Owned by `execute_pytest_in_judge0`                                                                                                                            |
| Ingestion orchestration                  | Thin HTTP router + `ingest_official_canvas_zip` service; shared ZIP/Canvas utilities in `extractor`                                                    | Keeps HTTP thin; worker re-extracts persisted ZIP                                                                                                              |
| Grading Workspace Isolation              | Skip copying model_solution artifacts to execution directory                                                                                           | Prevents student submissions from having their code overwritten by the instructor's reference solution during grading                                          |
| File I/O and Asset Injection             | Define input_file artifacts in config_json that are automatically copied to the student's sandbox directory                                            | Enables assignments to reference external static data files (like CSVs or text files) without requiring students to upload them                              |
| Multi-language / compiled pipelines      | Deferred                                                                                                                                               | Python Judge0 path only for now                                                                                                                                |

## Architecture notes (current)

- Official upload: [ingestion/router.py](../../backend/app/domains/ingestion/router.py) → [ingestion/service.py](../../backend/app/domains/ingestion/service.py).
- Grading: [grading/service.py](../../backend/app/domains/grading/service.py) orchestrates; [grading/executor.py](../../backend/app/domains/grading/executor.py) owns Judge0 pytest execution.
- AST checking remains source-string based (`check_student_code`); no path-level AST API.
