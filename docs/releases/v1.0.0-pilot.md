## 1. Executive Summary & Scope

The `v1.0.0-pilot` release establishes the validated production deployment for the Utah Valley University (UVU) CS 1400 and CS 1410 controlled course pilot. The platform operates on a single dedicated on-premises workstation (`10.115.20.200`, `CET-D24728`), delivering instantaneous, automated grading in isolated Kata microVMs alongside privacy-preserving, on-premises Socratic AI feedback powered by an NVIDIA RTX PRO 4500 GPU.

All pre-deployment release invariants, student sandbox pipelines, instructor batch intake workflows, microVM isolation boundaries, and automated FERPA zero-retention lifecycles have undergone comprehensive automated audit and end-to-end synthetic verification.

## 3. Kata microVM Sandbox Isolation & Execution Profile

All untrusted student code executes inside hardware-isolated Kata microVMs governed by QEMU and pinned runtime limits:

- **Hypervisor & Kernel Isolation:**
  - MicroVM Hypervisor: Kata Containers runtime-rs (`kata-runtime`) with QEMU (`accel=kvm`) and `virtiofsd`.
  - Guest Kernel: Independent Linux `6.18.35-202` inside Kata, completely separated from host kernel `6.17.0-1032-oem`.
  - Per-slot process separation: Each worker runs with dedicated `containerd-shim-kata-v2`, `virtiofsd`, and `qemu-system-x86_64` processes.
- **Pinned Grading Profile (Language ID 711):**
  - Base Image: `judge0/judge0:1.13.1` (`linux/amd64`, Debian Buster archive mirrors).
  - Python Binary: Compiled CPython 3.11.9 (`/usr/local/python-3.11.9/bin/python3.11`).
  - Core Tooling: `pip==24.3.1`, `setuptools==75.8.0`, `pytest==8.4.2`.
  - Allowed Course Libraries: `pillow==11.3.0`, `pygame==2.6.1`, `tabulate==0.9.0`.
  - Headless Drivers: `SDL_VIDEODRIVER="dummy"`, `SDL_AUDIODRIVER="dummy"`.
- **Sandbox Resource Caps & Timeout Envelopes:**
  - Memory Limit: Hard cap of 256 MB (`262,144 KB`) per execution box.
  - CPU Time Limit: 30.0s CPU time; 20.0s default wall time (`MAX_WALL_TIME_LIMIT=45s`).
  - Thread & Process Limit: Capped at 60 threads/processes per microVM box.
  - Upload Payload Cap: Strict 50 MB (`52,428,800 bytes`) limit enforced at intake.
- **Concurrency & Admission Tuning:**
  - `JUDGE0_MAX_CONCURRENT=6`: 6 dedicated Kata microVM execution slots.
  - Queue Thresholds: `HIGH_LOAD_THRESHOLD=50`, `FULL_QUEUE_THRESHOLD=75`.
  - AI Concurrency Bounds: `ai_max_concurrent=20`, `ai_max_waiting=30` (50 total admitted requests).

## 5. Operational Support Structure

Operational roles and emergency runbooks are formally documented in [`docs/guides/workstation.md`](../guides/workstation.md):

1. **Host & Infrastructure Administrator (`dev@10.115.20.200`):** Workstation hardware health, thermal/power monitoring, Kata/Docker daemon updates, `vllm-cs1410.service` maintenance, and daily `02:00` cron metadata backups (`backup_metadata.sh`).
2. **Course Coordinators (CS 1400 & CS 1410):** Assignment authoring, test harnesses, rubric criteria, model solution revalidation (`revalidate_references.py`), and rollout coordination.
3. **Teaching Assistants & Instructional Assistants (TAs / IAs):** Student sandbox guidance, active queue monitoring during lab sections, manual rubric scoring adjudication, and FERPA zero-retention adherence.
4. **Emergency Playbooks:** Documented incident recovery procedures for:
   - Ingestion halt & queue drainage (`sudo systemctl stop nginx`).
   - Service restart & worker recovery (`dc restart celery-worker dispatch-worker cleanup-worker`).
   - Local AI service outage & graceful degradation (`sudo systemctl restart vllm-cs1410.service`).
   - MicroVM hypervisor / sandbox lockup escalation (`dc restart judge0-worker judge0`).
   - Database disaster recovery & metadata restoration (`bash scripts/backup_metadata.sh --restore`).
