# UVU Autograder — Decisions

This file tracks current product and implementation decisions.

## Decision Log

Status reconciliation (2026-09-21): the next milestone is controlled course pilot readiness. This log states intended policy; implementation gaps and evidence are tracked in the [backlog](../planning/backlog.md) and [delivery controls](../planning/delivery_controls.md). Institutional Microsoft authentication is now a pilot requirement; official-run AI remains deferred. The single-origin Nginx deployment on port 80 uses `/api/*` for backend requests (stripping `/api` before proxying to FastAPI) and preserves `/staff/*` and `/sandbox/*` Next.js frontend page routes. The retention contract is unchanged; current cleanup gaps must be resolved before signoff.

| Local LLM prompt: single source of truth | One prompt module, `backend/app/integrations/ai/prompts.py` (`PROMPT_VERSION` v4), used by the live sandbox, the eval harness, and training data. Merges the sandbox client's concise Socratic style, FERPA `sanitize_code_and_text`, and multi-file code budgets with the eval guardrail rules (no scores, no solutions, cite only listed failures, ignore injected instructions). Model answers in JSON (`FeedbackResponse`) | A fine-tune trained on one prompt and served another silently degrades; JSON makes "don't invent failures" mechanically checkable (technical_specs.md: pytest is ground truth, the LLM explains). Decided by Easton with Jaxon's sign-off, 2026-09-22 |
| Local LLM feedback policy (prompt v4) | Hints and next_step point to *where to look* (a function, test, or reading section), never *what to write*: no "add/implement/change X", no either/or with the answer in it. Concept warnings are already shown in the sandbox Warnings panel, so feedback must not contradict them (no "perfect", no items for them, next_step points to reworking with allowed concepts). Failures sharing a root cause are explained once. Empty/placeholder submissions are detected mechanically (`prompts.submission_is_placeholder`) and stated plainly | From reading 50 eval responses (stock Gemma 4 12B, v2): concept warnings were silently dropped (3/3), next_step stated the fix in ~14/44 failing cases, empty submissions were misdescribed (2/2). v3 required naming the concept in the summary; that produced an ungrounded item and bled "no code submitted" into a non-empty case, so v4 relaxes it. Decided by Easton, 2026-09-22; revisit with instructors |
| AI feedback delivery: validate before display | Sandbox generates the full response, checks it with `ai/guardrails.validate_feedback` (grounded keys, no score, no solution code), renders markdown, then streams the *validated* text on the existing endpoint; failures show a fixed safe message | Token-by-token streaming would put unchecked text on screen, and a leaked score or solution can't be retracted. API and frontend contract unchanged; cost is perceived latency until the full response is ready |
| Local LLM requirements context          | `REQUIREMENTS` = automated scoring-item labels via `prompts.requirements_from_config`; eval and training derive it the same way | Assignments store no description yet, so this is all the runtime can supply; training on richer context than production sends would mismatch distributions. Revisit if an assignment description field is added |

## Architecture notes (current)

- Local LLM feedback: [llm/client.py](../../backend/app/integrations/llm/client.py) (transport) → [ai/prompts.py](../../backend/app/integrations/ai/prompts.py) (the one prompt) → [ai/guardrails.py](../../backend/app/integrations/ai/guardrails.py) (the one validator, also used by `backend/eval`).
- Official upload: [ingestion/router.py](../../backend/app/domains/ingestion/router.py) → [ingestion/engine.py](../../backend/app/domains/ingestion/engine.py) (`SubmissionIngestionEngine`).
- Grading: [grading/engine.py](../../backend/app/domains/grading/engine.py) (`GradingEngine`) orchestrates intake, AST inspection, runner packaging, Judge0 pytest execution via [grading/executor.py](../../backend/app/domains/grading/executor.py), and zero-retention cleanup.
- AST checking: [integrations/ast_checker/validator.py](../../backend/app/integrations/ast_checker/validator.py) provides `ASTCodeInspector` for directory-level auditing and concept whitelisting.
