# Serve venv only (~/venvs/serve). vLLM pins its own torch build; installing it
# into the training venv is exactly the torch-bump trap that breaks bitsandbytes.
#
#   python3.12 -m venv ~/venvs/serve
#   ~/venvs/serve/bin/pip install -r backend/training/requirements-serve.txt
#
# Gemma 4 12B is "Unified" (gemma4_unified): vLLM support merged in
# vllm-project/vllm#44429 (2026-06-03) and ships in every release from 0.23.0
# (the recipe page's "nightly required" note predates that). 0.29.0 is pinned
# rather than 0.30.0, which released the day this was written.
#
# Serve with the checkpoint's OWN chat template: do not pass --chat-template or
# --default-chat-template-kwargs. train_lora renders prompts with that template
# and its defaults, and a different template at serve time is exactly the
# train/serve mismatch this pipeline exists to prevent.
#
# Start it with VLLM_USE_FLASHINFER_SAMPLER=0 (see training/README.md): the Dell
# has no CUDA toolkit, and FlashInfer's sampler needs nvcc to JIT-compile.
vllm==0.29.0
